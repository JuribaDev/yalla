# Releasing yalla

This document captures the public release contract. Every release must keep it
true; if you change anything here, also update the relevant workflows and
package-manager metadata.

## Versioning

- Versions are SemVer, sourced from git tags shaped like `vX.Y.Z`.
- Command names, flag names, JSON envelopes, error codes, exit codes, and the
  on-disk config schema are public API. Breaking any of them requires a major
  bump and release notes.
- Build metadata (`yalla --version`) is stamped via `-ldflags` from the
  release tag.

## Channels

| Channel  | Source                                         | Notes                                                        |
|----------|------------------------------------------------|--------------------------------------------------------------|
| Manual   | GitHub Releases (`tar.gz` / `zip` + checksums) | Always shipped first. Other channels depend on these assets. |
| Homebrew | tap `JuribaDev/homebrew-yalla`                 | Generated by GoReleaser `brews:`.                            |
| Scoop    | bucket `JuribaDev/scoop-yalla`                 | Generated by GoReleaser `scoops:`.                           |
| WinGet   | PR into `microsoft/winget-pkgs`                | Generated by GoReleaser `winget:`.                           |
| npm/npx  | `yalla-cli` package                            | Trampoline that downloads the matching native binary.        |
| Go       | `go install github.com/JuribaDev/yalla/cmd/yalla@vX.Y.Z` | Contributor fallback; not a primary channel.                 |

## Workflows

- `.github/workflows/ci.yml` runs on every push/PR: gofmt, `go mod tidy`,
  `go vet`, `go test`, `go test -race`, and a GoReleaser snapshot dry-run
  (`goreleaser release --snapshot --clean --skip=publish`).
- `.github/workflows/release.yml` runs on `v*` tags: `goreleaser release
  --clean` followed by an npm publish step that stamps
  `npm/package.json#version` from the tag and runs `npm publish` if
  `NPM_TOKEN` is set.

## Required secrets

| Secret                       | Used by                  | Optional                     |
|------------------------------|--------------------------|------------------------------|
| `GITHUB_TOKEN`               | GoReleaser GitHub release | Provided automatically.      |
| `HOMEBREW_TAP_GITHUB_TOKEN`  | GoReleaser `brews`        | Required to publish formula. |
| `SCOOP_TAP_GITHUB_TOKEN`     | GoReleaser `scoops`       | Required to publish bucket.  |
| `WINGET_GITHUB_TOKEN`        | GoReleaser `winget`       | Required to open winget PRs. |
| `NPM_TOKEN`                  | npm publish step          | Required to publish wrapper. |

When a token is unset, the matching channel is skipped (`skip_upload: auto`
in `.goreleaser.yaml` and the `if: env.NPM_TOKEN != ''` guard on the npm
publish step).

## Local verification

```sh
# Required gates (no external tools)
gofmt -w .
go mod tidy
go vet ./...
go test ./...
go test -race ./...

# Optional, when goreleaser is installed locally
goreleaser check
goreleaser release --snapshot --clean
```

`go test ./internal/release/...` validates that the GoReleaser config and the
npm wrapper agree on the `<os>_<arch>` matrix, archive extensions, and
checksum filename. CI runs both the Go gates and `goreleaser check`, so a
broken release config trips on PR review.

## Release checklist

1. Update the Codebase Patterns and progress log if the public surface
   changed.
2. Tag the release: `git tag vX.Y.Z && git push origin vX.Y.Z`.
3. Watch the Release workflow finish without errors and confirm the GitHub
   Release shows checksums and binaries for every supported target.
4. Verify `yalla --version` and `yalla manifest --json` from at least one
   freshly installed channel (Homebrew or npm) before announcing the release.
