## Codebase Patterns

- Module path is `github.com/JuribaDev/yalla`. Go toolchain is 1.24+. The
  binary entrypoint lives at `cmd/yalla/main.go` and is intentionally tiny —
  it only wires `BuildInfo` and calls `internal/cli.Execute`.
- Cobra commands are constructed via injectable factories. The root factory is
  `cli.NewRootCommand(streams IOStreams, build BuildInfo) *cobra.Command`.
  Tests instantiate it with `*bytes.Buffer` streams; production passes
  `cli.DefaultIOStreams()`.
- `IOStreams{In, Out, ErrOut}` is the canonical stream bundle. **Cobra's own
  writers (`SetOut`, `SetErr`) are routed to stderr** to honor the
  stdout-is-data-only contract (help, usage, version, error banners are all
  diagnostics). Subcommands emit data via `IOStreamsFromContext(ctx).Out`.
- Persistent root flags are mirrored into a `*GlobalFlags` value and propagated
  to every subcommand through `WithGlobalFlags(ctx, …)` inside
  `PersistentPreRunE`. Subcommands read them via
  `GlobalFlagsFromContext(cmd.Context())`. Same pattern for `IOStreams` and
  `BuildInfo` (helpers `WithIOStreams`/`IOStreamsFromContext`,
  `WithBuildInfo`/`BuildInfoFromContext`).
- Required global flags (US-0001): `--json`, `--no-input`, `--config`,
  `--base-url`, `--token`, `--verbose` (`-v`), `--version`. Adding or renaming
  any of these is a public-API change and must update the registry test in
  `internal/cli/root_test.go`.
- Root command uses `Args: cobra.NoArgs` so unknown positional arguments fail
  loudly. Every command sets `SilenceErrors` and `SilenceUsage` so error
  rendering stays under the typed-error layer (US-0002 onward).
- Cobra 1.10's default help template skips `UsageString` unless the command is
  `Runnable` or has subcommands. Until subcommands exist, root needs an explicit
  `RunE: func(c, _) error { return c.Help() }` so `yalla` (no args) renders the
  full help with flags.
- Tests live next to the code they exercise. CLI tests construct the root via
  the factory, call `cmd.SetArgs(...)`, run `cmd.Execute()`, and assert against
  the in-memory buffers. Stdout-empty assertions are mandatory for any
  diagnostic path.
- Verification baseline: `gofmt -w .`, `go mod tidy`, `go vet ./...`,
  `go test ./...`, `go test -race ./...` — all must pass before commit.
  `goimports`, `golangci-lint`, `staticcheck`, `govulncheck`, and `goreleaser`
  are not yet installed locally and should be documented as missing rather
  than silently skipped.
- Release matrix (US-0009): `internal/release.SupportedTargets` is the canonical
  list of `(GOOS, GOARCH)` pairs yalla ships — linux/darwin/windows ×
  amd64/arm64. `Target.ArchiveName(version)` and `release.ChecksumsName(version)`
  mirror `.goreleaser.yaml`'s `archives[0].name_template` and
  `checksum.name_template`. Adding or removing a target is a public-API change
  and must update `.goreleaser.yaml > builds`, `npm/lib/platform.js`'s `OS_MAP`
  / `ARCH_MAP`, **and** `SupportedTargets` together. The tests in
  `internal/release/release_test.go` enforce the three-way contract.
- Distribution channels (US-0009): primary delivery is GoReleaser-built
  archives on GitHub Releases (tar.gz everywhere except Windows where it's
  zip). Channels layered on top: Homebrew tap (`JuribaDev/homebrew-yalla`),
  Scoop bucket (`JuribaDev/scoop-yalla`), WinGet PRs into
  `microsoft/winget-pkgs`, and the npm `yalla-cli` wrapper. Each channel is
  marked `skip_upload: auto` so missing tokens never break a release; CI
  runs `goreleaser check` and a `--snapshot --skip=publish` dry-run on
  every PR.
- npm wrapper contract (US-0009): the package is a *trampoline*. `bin/yalla.js`
  uses `child_process.spawn(..., { stdio: 'inherit' })` with no rewriting of
  argv, stdout, stderr, or exit codes. Postinstall failures must NOT abort
  `npm install` — the bin script retries the download on first run. The
  wrapper is intentionally zero-runtime-dependency; archive extraction uses
  the system `tar` (Win10+ ships `tar.exe`) with a PowerShell `Expand-Archive`
  fallback. Version resolution: `YALLA_VERSION` env first, then
  `package.json#version`. Release URL prefix is configurable via
  `YALLA_REPO` / `YALLA_RELEASE_BASE` for mirrors and tests.
- Build stamping (US-0009): the `cmd/yalla/main.go` `Version`/`Commit`/`Date`
  package vars are the *only* injection point. `.goreleaser.yaml > builds[0].
  ldflags` writes `-X main.Version`, `-X main.Commit`, and `-X main.Date`;
  do not add a parallel build-info location.
- Typed-error contract (US-0002): every user-visible failure is a
  `*errors.Error` from `internal/errors` with a stable `Code` (e.g.
  `E_NOT_FOUND`, `E_AUTH`, `E_NETWORK`, `E_USAGE`, `E_NO_INPUT_REQUIRED`).
  `Code.ExitCode()` is the public exit-code map; do not return a plain
  `fmt.Errorf` from a subcommand's `RunE` — it falls through to
  `E_INTERNAL` (exit 1).
- Output contract (US-0002): all command output flows through
  `internal/output.Renderer`, constructed once per invocation. Success JSON
  uses schema_version `yalla.output.v1`; error JSON uses
  `yalla.error.v1`. `Renderer.Human` is auto-suppressed in `--json` mode so
  stdout stays single-document JSON. `Renderer.Logf` always goes to stderr.
- Secret redaction (US-0002): `output.NewRedactor(flags.Token)` is the
  defence-in-depth scrubber applied to every visible string. It also matches
  `Authorization: ...`, `X-API-Key: ...`, and `?token=`/`?api_key=` query
  params even when the literal secret is unknown. Sentinel is `[REDACTED]`
  and is part of the public contract.
- Top-level error rendering: `internal/cli/error_render.go::renderTerminalError`
  is the **only** place a top-level cobra failure is printed. It calls
  `errors.From(err)` to map cobra parse errors (`unknown command`,
  `unknown flag`, `required flag`, …) to `CodeUsage` (exit 2). The renderer
  reads `flags.JSON` and `flags.Token` directly from the bound `*GlobalFlags`
  pointer returned by `buildRoot`, so JSON envelopes and redaction work even
  when cobra fails before `PersistentPreRunE` runs.
- `cli.Execute` is now a one-liner over `executeWith(streams, build)`. Tests
  drive `executeWith` via `runExecuteWith(t, sub, args...)` to assert exit
  codes, JSON envelopes, and stdout silence on failure.
- Config layer (US-0003): `internal/config.Loader.Load(FlagValues)` is the
  ONLY config entry point. `PersistentPreRunE` calls it once, stashes the
  resolved `*config.Config` on the command context via `config.WithConfig`,
  and mirrors the resolved values back into `*GlobalFlags`. Subcommands read
  via `config.FromContext(ctx)`; never call `Load` from a `RunE`.
- Config precedence (US-0003): CLI flag > env var > config file > default.
  The flag layer respects the parse-time `Changed` bit so an unchanged flag
  never beats a lower source. Env var names (`YALLA_BASE_URL`, `YALLA_TOKEN`,
  `YALLA_CONFIG`, `YALLA_OUTPUT`, `YALLA_NO_INPUT`) and config keys
  (`base_url`, `token`, `output`, `no_input`, `verbose`) are public API.
- On-disk config (US-0003): YAML via `gopkg.in/yaml.v3` with
  `Decoder.KnownFields(true)` so typos fail fast. Files are written with
  0600 inside a 0700 parent directory (`internal/config.WriteFile`). Path is
  cross-platform via `os.UserConfigDir`. **Missing files are never an
  error** regardless of how the path was supplied — yalla works out of the
  box.
- Config validation (US-0003): base URL is validated at load time
  (http/https scheme + non-empty host) so dial errors don't leak from deep
  in the call stack. `YALLA_OUTPUT` accepts `json`/`human`/`text`;
  `YALLA_NO_INPUT` accepts the relaxed bool grammar (`1`/`true`/`yes`/`on`
  and inverses).
- Renderer env fallback (US-0003): cobra parse failures happen *before*
  `PersistentPreRunE`, so `internal/cli/error_render.go` consults
  `envSnapshotForRenderer()` (a package var, mockable in tests) which calls
  `Loader.SnapshotForRenderer()` for YALLA_OUTPUT/YALLA_TOKEN-only
  configurations. JSON envelopes and redaction stay honoured even on usage
  failures.
- Subcommand renderer construction (US-0003): use the `rendererFromContext`
  helper inside any `RunE`. It builds an `output.Renderer` from the resolved
  `IOStreams` + `*GlobalFlags`, seeded with the secret redactor — hand-
  rolling a Renderer in a command body skips the redactor and is a contract
  violation.
- Test isolation (US-0003): `internal/cli/main_test.go::TestMain` unsets
  every YALLA_* env var and pins `envSnapshotForRenderer` to an empty
  snapshot. Tests that mutate env (`t.Setenv`) cannot use `t.Parallel`; the
  `withTempConfig(t, contents)` helper centralises the YALLA_CONFIG fixture.
- E2E command tests (US-0003): use `runRootArgs(t, args...)` from
  `internal/cli/config_cmd_test.go`. It runs `buildRoot` + `cmd.Execute` +
  `renderTerminalError` so the captured stderr matches what the binary
  prints in production. Calling `cmd.Execute` alone hides the typed banner
  because of `SilenceErrors`.
- API registry (US-0004): the Dokploy OpenAPI 3.1 document is embedded
  via `//go:embed data/openapi.json` inside `internal/api`.
  `api.EmbeddedSpecSHA256` pins the digest; bumping the spec is a public-
  API change and must update that constant, `ralph/prd.json`'s
  `sourceApi.sha256`, and the `expectedOperationCount` constant in both
  `internal/api/registry_test.go` and `internal/cli/api_cmd_test.go`.
- Registry access (US-0004): use `api.Default()` for the singleton
  registry — it parses the embedded spec exactly once. Operations are
  exposed in **operationId-sorted** order; never assume path or method
  order. `Operation` fields use `json.RawMessage` for schemas so the
  full OpenAPI/JSON Schema surface (oneOf, $defs, examples) survives
  round-trip.
- Schema extraction (US-0004): `Registry.Schema(opID)` returns a typed
  `*SchemaDoc` with `Input` (parameters + body) and `Outputs` (per-status
  responses). `Registry.AllSchemas()` materialises every schema for
  manifest-style consumers. Both projections preserve raw JSON bodies.
- Inspection commands (US-0004): `yalla api operations [--tag T]`,
  `yalla schema list`, and `yalla schema get <opID>` are all read-only
  and route through `rendererFromContext`. Their JSON envelopes always
  include `spec_title`/`spec_version`/`spec_sha256` so agents can verify
  the exact Dokploy revision the binary was built against. Unknown tags
  map to `E_INVALID_INPUT` (exit 2); unknown operationIds map to
  `E_NOT_FOUND` (exit 5).
- Error envelopes go to **stderr** (`renderTerminalError` passes
  `streams.ErrOut` to `output.Renderer.Error`). On any error path stdout
  must remain empty even when `--json` is set; tests assert
  `stdout == ""` and `strings.Contains(stderr, "yalla.error.v1")`.
- HTTP client (US-0006): `internal/api.NewClient(api.ClientConfig)` is
  the **only** way to talk to Dokploy. The package never imports
  `internal/config` or `internal/cli`; the CLI layer translates
  `*config.Config` into a `ClientConfig` so `internal/api` stays a
  pure library.
- Client contract (US-0006): `Client.Do(ctx, *Request) (*Result, error)`
  returns `(*Result, nil)` for **any** completed HTTP transaction —
  including 4xx/5xx — so callers pick the policy. Transport-level
  failures (timeout, cancel, dns, dial, TLS) are typed `*yerr.Error`
  values with `CodeTimeout`/`CodeCanceled`/`CodeNetwork`. Use
  `Result.AsError()` for the canonical HTTP-status to error-code
  mapping (400/422→`InvalidInput`, 401→`Auth`, 403→`Forbidden`,
  404→`NotFound`, 409/412→`Conflict`, 429→`RateLimited`, 5xx→`Server`).
- Retry policy (US-0006): retries fire only when `Request.Idempotent`
  is true AND `ClientConfig.MaxRetries > 0`. Triggers are
  network/timeout errors and HTTP 502/503/504 (500 is treated as a
  deterministic application bug and never retried). Backoff is
  context-aware — `<-ctx.Done()` during a retry sleep returns
  `CodeCanceled` rather than waiting out the timer.
- HTTP client tests (US-0006): always use `httptest.Server` or a stub
  `http.RoundTripper` (`roundTripperFunc` in `client_test.go`); never
  point a test at a live host. Set `RetryBase: 0` so the retry loop
  runs without sleeping. `t.Context()` (Go 1.24) is the canonical
  request-scoped context for these tests.
- Raw API executor (US-0005): `yalla api call <operationId>` lives in
  `internal/cli/api_call_cmd.go` and is the **only** cli-side caller
  of a live HTTP transaction. The HTTP client is built through
  `apiCallClientFactory(apiCallClientArgs)` — a package var that tests
  override to inject stub `http.RoundTripper`s or per-attempt timeouts.
  Restore the original via `t.Cleanup`.
- `--input` schema (US-0005): closed JSON shape `{path_params, query,
  headers, body}` decoded with `json.Decoder.DisallowUnknownFields()`.
  A misspelled key fails fast as `E_INVALID_INPUT`. `query` and
  `headers` are `map[string][]string` so repeats work without a custom
  grammar. `body` is `json.RawMessage` so number precision and key
  order survive the round-trip. `--input -` reads from `streams.In`
  (NOT a prompt — explicit stdin is part of the requested data source,
  so `--no-input` does not block it).
- HTTP idempotency policy (US-0005): only `GET` and `HEAD` are flagged
  `Idempotent: true` on the `api.Request`. POST/PUT/DELETE/PATCH are
  never retried automatically because Dokploy's POST surface is
  mutating. Retries default to **zero** in the executor's factory —
  agents that want them must opt in explicitly via a future flag.
- HTTP status mapping (US-0005): every non-2xx response goes through
  `result.AsError()` so the canonical table (400/422→InvalidInput,
  401→Auth, 403→Forbidden, 404→NotFound, 409/412→Conflict,
  429→RateLimited, 5xx→Server) lives in **one** place
  (`internal/api/client.go::classifyStatus`). Do not re-translate
  status codes inside cli commands.
- Pre-flight guards (US-0005): missing base URL → `E_CONFIG`,
  missing token on an auth-required op → `E_AUTH`, both BEFORE
  constructing the HTTP client so `--no-input` workflows fail
  deterministically without a wire round-trip. Both checks are
  skipped in `--dry-run` so an agent can validate request
  construction offline.
- Dry-run rendering (US-0005): the `Authorization` header is
  rewritten to `Bearer [REDACTED]` (the `output.Sentinel`) before
  emission so a dry-run envelope is safe to log or paste. The
  output redactor still scrubs the literal token value as a
  defence-in-depth.
- Manifest contract (US-0007): `yalla manifest --json` is the single
  introspection surface for agents. The envelope is the standard
  `yalla.output.v1`; the inner payload carries its own
  `manifest_schema` (`yalla.manifest.v1`). It bundles binary
  metadata, the resolved spec digest, persistent global flags, the
  full command tree (with per-command flags + examples), the
  canonical error-code table from `errors.AllCodes()`, and the
  registry coverage (`operations.{total,tags,ids}`). Adding any
  new top-level command requires updating
  `TestManifest_JSONListsAllSubcommands` so the manifest contract
  stays explicit.
- Error-code catalogue (US-0007): `internal/errors.AllCodes()` is the
  source of truth for the `(Code, ExitCode, Description)` triples
  exposed by the manifest. Adding a new `Code` constant requires
  adding a description to `codeDescriptions` in the same file —
  `TestManifest_JSONListsAllErrorCodes` enforces parity.
- Cobra introspection (US-0007): `collectCommandTree` and
  `collectFlagSet` (in `internal/cli/manifest_cmd.go`) are the
  canonical projections for any command/flag introspection.
  `isInternalCobraCmd` filters Cobra's `help` and `__complete*`
  helpers; the auto-added `completion` subcommand is suppressed in
  `buildRoot` via `cmd.CompletionOptions.DisableDefaultCmd = true`
  so yalla's own `completion` tree is the sole owner of that
  surface.
- Docs generator (US-0007): `yalla docs markdown` emits one Markdown
  file per command into `--output-dir` (file names join the path
  with underscores), or a single combined doc to stdout when the
  flag is omitted. With `--json`, the file path returns
  `{format,command_count,output_dir,files}`; the stdout path returns
  `{format,command_count,content}`. Future formats (man, html) plug
  in as new subcommands of `yalla docs`.
- Completion generator (US-0007): `yalla completion <shell>` reuses
  Cobra's built-in generators (`GenBashCompletionV2`,
  `GenZshCompletion`, `GenFishCompletion`,
  `GenPowerShellCompletionWithDesc`). Adding a shell means appending
  to `supportedShells` AND extending `generateCompletion`. Scripts
  go to stdout verbatim; with `--json` they wrap in
  `{shell,script}`. The completion path is the only command that
  legitimately writes raw bytes to `Renderer.Out()` because shell
  scripts cannot tolerate substring redaction (and yalla never
  embeds tokens in completion output).
- Verification harness (US-0008): `internal/testutil` is the shared
  test toolbox for every command, API, and contract test going
  forward. `testutil.Run`/`RunArgs` drives the production exit-code
  path through the new exported `cli.ExecuteForTest` seam — never
  call `cli.NewRootCommand` + `cmd.Execute` directly from tests
  because that bypasses `renderTerminalError` and loses the typed
  banner. `IsolateEnv(t)` clears every `YALLA_*` env var and
  `WriteTempConfig(t, contents)` seeds a per-test config without
  threading `--config` through every assertion.
- Envelope assertions (US-0008): `DecodeSuccess`/`DecodeSuccessInto`
  for `yalla.output.v1`, `DecodeError`/`AssertExitForCode` for
  `yalla.error.v1`. `MustBeValidJSON` is the bedrock single-document
  check; `AssertStdoutEmpty`/`AssertStderrEmpty` enforce the data-
  only stdout contract; `AssertNotContains` is the secret-leak
  regression net (pass the literal token).
- Golden workflow (US-0008): `Golden(t, name, got, opts)` and
  `GoldenJSON(t, name, got, normalisers...)` write to
  `testdata/<name>.golden`. Run `go test -update-golden ./...` to
  regenerate. Always pair JSON goldens with
  `testutil.DefaultJSONNormalizers()` so request_id / trace_id /
  duration_ms / timestamps stay deterministic across runs. Tests
  that exercise the comparison branch must call
  `SetUpdateGoldenForTest(t, false)` so a developer running
  `-update-golden` for an unrelated package does not silently mask
  logic regressions.
- HTTP fixtures (US-0008): `testutil.NewServer(t, handler)` is the
  everyday Dokploy stand-in (it wires `YALLA_BASE_URL`,
  `YALLA_TOKEN`, and `t.Cleanup` in one call) and returns the
  seeded token so secret-leak assertions have a literal value to
  compare. `RecordingServer(t, handler)` wraps that with a request
  recorder so contract tests can assert exactly what was sent.
  `LookupOperation(t, opID)` resolves an operation from
  `api.Default()` and fails the test with a hint when the id is
  missing. `RoundTripperFunc` is the bypass for transport-level
  error injection.
- Cobra arg fallback (US-0008): `cli.ExecuteForTest` normalises a
  `nil` args slice to `[]string{}` before calling `cmd.SetArgs`.
  Without that, cobra falls back to `os.Args[1:]`, which inside a
  `go test` binary carries `-update-golden` and any other
  test-specific flag — leaking them into the command tree always
  produced E_USAGE.

- **Implemented**: Bootstrap of the Yalla Go module and Cobra root command.
  Created the production project skeleton with an injectable Cobra factory,
  context-propagated global flags / streams / build info, and unit tests that
  drive the command tree through in-memory buffers.
- **Files changed**:
  - `go.mod` (new) — module `github.com/JuribaDev/yalla`, Go 1.24, requires
    `github.com/spf13/cobra v1.10.2`.
  - `go.sum` (new) — populated by `go mod tidy`.
  - `cmd/yalla/main.go` (new) — thin entrypoint that wires `BuildInfo`
    (Version/Commit/Date stamps overridable via `-ldflags`) and exits on the
    code returned by `cli.Execute`.
  - `internal/cli/root.go` (new) — `IOStreams`, `GlobalFlags`, `BuildInfo`,
    context accessors, `NewRootCommand`, `Execute`. Cobra's writers are routed
    to stderr; persistent flags `--json`, `--no-input`, `--config`,
    `--base-url`, `--token`, `--verbose` (`-v`), and the implicit `--version`

    rejects stray positional arguments.
  - `internal/cli/root_test.go` (new) — covers: stdout stays empty when no

    `-v` shorthand, persistent pre-run propagates flags / streams / build info
    to subcommands, `--version` prints the build line, `--help` keeps stdout
    empty, unknown commands fail without leaking to stdout, and context
    accessors return safe fallbacks when called with a bare `context.Background`.
  - `internal/cli/AGENTS.md` (new) — module-local conventions for future CLI
    contributors and agents.
  - `ralph/prd.json` — set US-0001 `passes: true`.
- **Verification run**:
  - `gofmt -w .` — clean (no files reformatted).
  - `go mod tidy` — clean.
  - `go vet ./...` — clean.
  - `go test ./...` — `ok github.com/JuribaDev/yalla/internal/cli`.
  - `go test -race ./...` — `ok github.com/JuribaDev/yalla/internal/cli`.
  - `go build ./...` — clean.
  - Smoke: `go run ./cmd/yalla --version` → `yalla 0.0.0-dev (commit unknown,
    built unknown)`. `go run ./cmd/yalla` (no args) → empty stdout, full help
    on stderr including every required flag.
- **Tools NOT available locally** (documented per the verification policy):
  `goimports`, `golangci-lint`, `staticcheck`, `govulncheck`, `goreleaser`.
  Future stories must either install these or treat their absence the same way.
- **Remaining risks / follow-ups**:
  - `--version` output currently writes through Cobra's writer (now stderr) to
    keep the stdout-is-data rule airtight; the future `yalla version --json`
    subcommand will be the data-shaped path.
  - Typed error envelopes / stable exit codes are stubbed only at the binary
    layer (`Execute` returns 1 on failure, surfacing the message on stderr).
    The full envelope and exit-code contract land in US-0002.
  - No real subcommands yet; the unknown-command guard is `cobra.NoArgs` on
    root rather than Cobra's automatic suggestion engine. Once subcommands
    exist, also wire `cmd.SuggestionsMinimumDistance` for nicer errors.
- **Learnings for future iterations**:
  - Cobra 1.10 will not render `UsageString` from the default help template
    when a command is neither `Runnable` nor has subcommands. The fix is
    either to set a `RunE` that returns `c.Help()` (used here) or to register
    subcommands. Without one of those, `yalla` with no args prints only the
    `Long` description.
  - `cmd.SetOut(stderr)` is the cleanest way to keep Cobra-managed output
    (help, usage, --version template) off of stdout. Subcommands must NOT use
    `cmd.Print/Println` for data; route data through
    `IOStreamsFromContext(ctx).Out` instead.
  - `PersistentPreRunE` is the right place to populate the command context.
    Cobra propagates the context to children during `Execute`/`ExecuteContext`,
    so flag values bound by `pflag` are guaranteed to be parsed before the
    subcommand's `RunE` reads them via `GlobalFlagsFromContext`.
  - Tests should always assert `stdout.Len() == 0` on diagnostic paths — it is
    the cheapest way to catch a future regression in the stdout contract.
  - `cobra.NoArgs` on the root catches `yalla bogus` early; otherwise Cobra
    silently runs root with a positional arg.

## 2026-05-08 - US-0002
- **Implemented**: Agent-first output, error, and exit-code contracts. Three
  new packages plus the wiring that makes every top-level cobra failure a
  typed error rendered as either a `yalla.error.v1` JSON envelope (when
  `--json` is set) or a stable `Error [CODE]: msg` / `  hint: …` line on
  stderr. Stdout stays data-only on every error path; secret redaction is
  applied to every visible string.
- **Files changed**:
  - `internal/errors/errors.go` (new) — `Error`, `Code` constants
    (`E_USAGE`/`E_INVALID_INPUT`/`E_CONFIG`/`E_AUTH`/`E_FORBIDDEN`/
    `E_NOT_FOUND`/`E_CONFLICT`/`E_RATE_LIMITED`/`E_SERVER`/`E_NETWORK`/
    `E_TIMEOUT`/`E_CANCELED`/`E_NO_INPUT_REQUIRED`/`E_UNSUPPORTED`/
    `E_INTERNAL`/`E_UNKNOWN`), the public `Code.ExitCode()` map (0/1/2/3/

    errors to `CodeUsage`, and `SchemaVersion = "yalla.error.v1"`.
  - `internal/errors/errors_test.go` (new) — covers exit-code stability,
    nil-receiver safety, hint copy-on-write, `errors.Is`/`As` traversal

  - `internal/errors/AGENTS.md` (new).
  - `internal/output/output.go` (new) — `Renderer` with `Data` (JSON
    envelope, no-op in human mode), `Human` (text, no-op in JSON mode),

    or human banner), `Raw` (passthrough), and accessors.
  - `internal/output/envelope.go` (new) — `successEnvelope`, `errorEnvelope`,
    `errorPayload` with `hint,omitempty`. `SuccessSchema =

  - `internal/output/redact.go` (new) — `Redactor` with `Sentinel =

    completed its single request. The current tests rely on `Do()`'s
    return as the synchronisation point — handler writes happen-before
    `Do()` returns because the body is fully read on the server side
    before the response completes. For multi-request races, switch to
    `sync/atomic` (already used for retry-counter assertions).
  - For transport-error tests, prefer a stub `http.RoundTripper` over
    pointing the client at an unreachable host: it sidesteps platform-
    specific dial timeouts (Linux ~127s, macOS varies) and keeps the
    suite under a second.
  - Cobra's `SilenceErrors` / `SilenceUsage` pattern from US-0001 keeps
    the renderer in charge of error output, which means `*yerr.Error`
    values returned from `client.Do` flow through the same redactor as
    a typed config error. No new error-rendering code was needed for
    this story.
  - The retry policy distinguishes 502/503/504 from 500 because 500 is
    almost always a deterministic application bug that re-running won't
    fix; 502/503/504 are upstream/gateway failures that often clear on
    a single retry. Document the distinction in the AGENTS.md so US-0005
    inherits it.

- **Learnings for future iterations**:
  - **GoReleaser v2 schema**: archives use `formats: [tar.gz]` (plural,
    array). `format` (singular) silently parses but produces no archive.
    `format_overrides` follows the same shape. Modeling the YAML in a
    Go test with `KnownFields(false)` lets us assert the keys we care
    about without fighting the rest of the schema.
  - **Token guards**: setting `skip_upload: auto` on every brew/scoop/winget
    channel plus an `env:` block that defaults the token vars to
    `placeholder` makes a fork PR's snapshot dry-run pass without secrets.
    The release workflow still uses the real tokens via
    `${{ secrets.* }}`.
  - **Cross-platform extraction**: the Windows-10+ `tar.exe` accepts zip
    archives transparently, so `tar -xf <archive> -C <dir>` is the single
    extraction command for both `.tar.gz` and `.zip`. PowerShell
    `Expand-Archive` only fires on the rare missing-tar.exe case.
  - **Node child stdio**: `spawn(bin, args, { stdio: 'inherit' })` is the
    only correct trampoline pattern. Anything that pipes through Node
    (e.g. `spawnSync` returning buffers) silently breaks the
    "stdout-is-data-only" agent contract on the first command that
    emits binary or non-UTF8 bytes.
  - **Project-root discovery in tests**: `runtime.Caller(0)` + walking
    parents until `go.mod` is found beats hard-coding `../..`. Tests stay
    valid through package moves and survive `go test ./...` invocations
    from any working directory.
  - **npm `os` / `cpu` fields**: declaring the supported tuples in
    `package.json` lets npm refuse the install on truly unsupported
    platforms before postinstall runs, so the user sees a clean error
    instead of a wrapper-side "unsupported platform" crash. Keep it in
    sync with `release.SupportedTargets`.
  - **Checksum file format**: GoReleaser writes `<hex>  <filename>` per
    line, sometimes with a leading `*` (binary mode flag from coreutils).
    `parseChecksum` strips the `*` and lowercases the hex so the wrapper
    survives both shapes.
