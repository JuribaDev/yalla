## Codebase Patterns
- Backend code lives under internal/controlplane/<pkg>; CLI stays under internal/cli. Keep HTTP handlers thin.
- Shared primitives are reused, not reinvented: typed errors come from internal/errors (yerr.New/Newf, CodeConfig, etc.); the redaction sentinel and Redactor come from internal/output.
- API success envelopes use yalla.output.v1; API errors use yalla.error.v1 (see internal/controlplane/httpapi/server.go).
- Config is env-only for backend processes (no flags/files): internal/controlplane/config.Load(LookupFunc) layers env vars over per-profile defaults, then validates. cmd/yalla-api and cmd/yalla-worker call config.LoadFromEnv() once at startup and os.Exit(1) on error.
- Every config/validation failure is a typed yerr CodeConfig error and must NEVER echo a secret value. Tests assert secrets do not appear in error strings, Redacted(), LogValue(), or String().
- Secret-bearing structs implement slog.LogValuer + fmt.Stringer with redacted views as defence-in-depth.
- Tests inject dependencies (e.g. config.MapLookup) instead of touching real process env/filesystem. Use t.Parallel().
- Quality gate before commit: gofmt -w ., go mod tidy, go build ./..., go vet ./..., go test ./..., go test -race ./....
- Process lifecycle is owned by internal/controlplane/runtime: RunHTTPServer(ctx, srv, shutdownTimeout, logger) for the API and worker.Loop for background jobs. Backend binaries derive shutdown from one signal.NotifyContext and pass cfg.ShutdownTimeout; they do not hand-roll select/Shutdown blocks.
- runtime.Readiness holds named startup gates (concurrency-safe). httpapi.NewHandler takes a runtime.ReadinessReporter; /readyz must be 503 yalla.error.v1 E_SERVER until every gate passes, 200 yalla.output.v1 after. /healthz is liveness-only and never depends on downstream checks.
- worker.Loop depends only on the Claimer/Lease interfaces so the durable job store can land later. The loop checks ctx before every Claim (stop claiming on shutdown) and releases interrupted in-flight leases on a context.WithoutCancel context so the release survives shutdown. A job whose Run returns nil is committed and must never be released.
- Lifecycle code is tested with fakes (fake httpServer, fake Claimer/Lease) — no real sockets, no live deps.

- Learnings for future iterations:
  - RunHTTPServer takes an unexported httpServer interface ({ListenAndServe; Shutdown}); *http.Server
    satisfies it and tests pass a fake — exported func + unexported interface param works fine.
  - Lease.Run's contract: nil return == committed (never release); non-nil + shutdown == release.

  - context.WithoutCancel (Go 1.21+) is the clean way to give shutdown-time cleanup work a context
    that is not already cancelled. go.mod is on go 1.25.
  - Adding a non-secret config field only needs Config + Load + Validate + Redacted/LogValue/String
    + tests; the redaction tests only assert secrets are absent, so a new plain field is safe.
