## Codebase Patterns
- Backend code lives under internal/controlplane/<pkg>; CLI stays under internal/cli. Keep HTTP handlers thin.
- Shared primitives are reused, not reinvented: typed errors come from internal/errors (yerr.New/Newf, CodeConfig, etc.); the redaction sentinel and Redactor come from internal/output.
- API success envelopes use yalla.output.v1; API errors use yalla.error.v1. ALL HTTP responses render through internal/controlplane/apienvelope (WriteData/WriteError/WriteErrorStatus); envelope structs are unexported so handlers cannot hand-roll JSON. HTTP status derives from the error Code via apienvelope.StatusForCode (WriteErrorStatus is the explicit-override escape hatch, e.g. /readyz 503). Error envelopes carry documentation_url; apienvelope is also a regex-based redaction backstop for message/hint/warnings.
- Config is env-only for backend processes (no flags/files): internal/controlplane/config.Load(LookupFunc) layers env vars over per-profile defaults, then validates. cmd/yalla-api and cmd/yalla-worker call config.LoadFromEnv() once at startup and os.Exit(1) on error.
- Every config/validation failure is a typed yerr CodeConfig error and must NEVER echo a secret value. Tests assert secrets do not appear in error strings, Redacted(), LogValue(), or String().
- Secret-bearing structs implement slog.LogValuer + fmt.Stringer with redacted views as defence-in-depth.
- Tests inject dependencies (e.g. config.MapLookup) instead of touching real process env/filesystem. Use t.Parallel().
- Quality gate before commit: gofmt -w ., go mod tidy, go build ./..., go vet ./..., go test ./..., go test -race ./....
- Process lifecycle is owned by internal/controlplane/runtime: RunHTTPServer(ctx, srv, shutdownTimeout, logger) for the API and worker.Loop for background jobs. Backend binaries derive shutdown from one signal.NotifyContext and pass cfg.ShutdownTimeout; they do not hand-roll select/Shutdown blocks.
- runtime.Readiness holds named startup gates (concurrency-safe). httpapi.NewHandler takes a runtime.ReadinessReporter; /readyz must be 503 yalla.error.v1 E_SERVER until every gate passes, 200 yalla.output.v1 after. /healthz is liveness-only and never depends on downstream checks.
- worker.Loop depends only on the Claimer/Lease interfaces so the durable job store can land later. The loop checks ctx before every Claim (stop claiming on shutdown) and releases interrupted in-flight leases on a context.WithoutCancel context so the release survives shutdown. A job whose Run returns nil is committed and must never be released.
- Lifecycle code is tested with fakes (fake httpServer, fake Claimer/Lease) — no real sockets, no live deps.
- Request correlation lives in internal/controlplane/telemetry. telemetry.Correlate is the outermost HTTP middleware (httpapi.NewHandler wraps the mux in it): it resolves request_id (per request) + correlation_id (per workflow) onto the request context before any handler runs. Inbound X-Request-Id/X-Correlation-Id are honoured only if telemetry.SafeID passes ([A-Za-z0-9._-], 1..128) — unsafe values are dropped and a fresh telemetry.NewRequestID() is minted, so injection payloads never reach headers/logs/jobs. Read IDs anywhere via telemetry.FromContext/RequestID/CorrelationID; never thread them through signatures. Non-HTTP entry points seed context with telemetry.WithCorrelation.
- Per-request structured logging lives in internal/controlplane/telemetry: telemetry.RequestLogging(logger) is the middleware just inside Correlate (httpapi.NewHandler wraps the routed mux in it). One JSON record per request: method/route/target/status/latency_ms/bytes/request_id/correlation_id, plus org_id/principal_id when set via telemetry.SetOrgID/SetPrincipalID (a request-scoped mutable holder the auth/policy layers enrich). Headers and bodies are never logged; the request target is redacted. Level follows the outcome (5xx error, 4xx warn, else info); the logger threshold (YALLA_LOG_LEVEL) gates emission. Service binaries bind service via logger.With and log JSON to stdout.
- Backend errors are built through internal/controlplane/apierr, the catalogued error taxonomy — never yerr.New directly in handlers/services. apierr constructors return *yerr.Error (so they flow into apienvelope.WriteError); apierr.Catalog/Lookup pair every code with HTTP status (derived from apienvelope.StatusForCode — single source of truth), retry semantics, and a MessagePolicy. MessageGeneric codes (internal + all dependency failures) keep the cause out of Message/Hint and only Wrap it for logging. InvalidInput carries FieldViolation{Field,Reason} (path + reason, never the submitted value), recoverable via apierr.ViolationsOf; dependency failures are recoverable via apierr.DependencyOf even when they share a code. Adding a code = define the yerr.Code constant in internal/errors (and its codeDescriptions, AllCodes, ExitCode entries — the code is shared with the CLI manifest) + add to apierr.taxonomy + add an apierr constructor + (if non-500) a apienvelope.StatusForCode case; update the TestStatusForCode / TestConstructorsEmitCataloguedCodes / TestCode_ExitCodeMappingIsStable tables.
- Schema changes are versioned SQL files under internal/controlplane/store/migrate/migrations/ named NNNN_name.up.sql (required) + NNNN_name.down.sql (optional, reversible-only), embedded via //go:embed. The migrate.Migrator runner owns a checksummed schema_migrations ledger, serialises with a pg advisory lock, and runs each migration in its own transaction. Migrator.Up is idempotent and refuses dirty / unknown-version / checksum-mismatch databases (errors.Is sentinels ErrDirtyDatabase/ErrUnknownVersion/ErrChecksumMismatch). NEVER edit an applied migration file (trips ErrChecksumMismatch by design) — add a new higher-versioned migration. Persistence tests are integration tests: they connect via YALLA_TEST_DATABASE_URL, create an isolated throwaway database per test, and t.Skip when the env var is unset so go test ./... stays green without Postgres. docker-compose.yml at repo root provisions local Postgres. pgx (github.com/jackc/pgx/v5 + pgxpool) is the Postgres driver.
- Persistence tests use the shared harness internal/controlplane/testutil: RequireDB(t) gives an empty isolated throwaway Postgres database per test, RequireMigratedDB(t) also applies migrations; both t.Skip with testutil.SkipReason when YALLA_TEST_DATABASE_URL is unset and drop the DB on cleanup (parallel-safe — unique DB name per call). testutil.NewFactory(t) builds deterministic, globally-unique in-memory fixtures for the Organization->Project->Environment->Service hierarchy + User/APIKey (two factories never collide). testutil.AssertRedacted/AssertRedactedValue guard "must not leak a secret" assertions. store/migrate keeps its own local testPool — it cannot import testutil (import cycle: testutil imports migrate). Keep pure decision logic (lookupAdminDSN, scanLeaks) unexported + white-box tested, since testing.TB is sealed and cannot be faked.
- HTTP routes are data-driven from internal/controlplane/httpapi/routes.go newRouteTable — the single source of truth. Each apiRoute pairs a served http.HandlerFunc with its openapi.Endpoint metadata; httpapi.NewHandler registers every entry on the mux AND generates the OpenAPI document from the same table, so a served route is always a documented route (TestEveryRegisteredRouteIsDocumented enforces it in CI). Never call mux.HandleFunc directly in NewHandler — add to newRouteTable. The OpenAPI 3.1 document is built by internal/controlplane/openapi.Build from a neutral []openapi.Endpoint, references the two stable envelope schemas, is served raw (not enveloped) at GET /openapi.json without auth, and marshals maps with sorted keys for a byte-stable artifact. Secret-shaped sample values use output.Sentinel.
- Domain tables live in versioned migrations under store/migrate/migrations/. Every customer-data table carries organization_id (directly or via a verified parent chain) and is tenant-isolated at the database level by COMPOSITE foreign keys: a child FK (organization_id, parent_id) references the parent's UNIQUE (organization_id, id), making a cross-tenant child unrepresentable. Slugs are citext, unique within parent scope, never global. users is a global identity table; org membership is the memberships join table. Schema-level integration tests live in package store_test (NOT package migrate — it can't import testutil) and match constraint violations via *pgconn.PgError SQLSTATE class 23.
- Persistence access goes through internal/controlplane/store: Store.Read (read-only tx -> Querier) and Store.Write (read/write tx -> *Tx; commit on nil, rollback on ANY error or panic). A *Tx is obtainable ONLY inside Store.Write; repository mutation methods take *Tx, read methods take Querier — so a mutation structurally cannot run outside the transaction that also carries its authorization and quota checks. A unit of work validates input first, then composes authorize -> reserve quota -> write desired state -> enqueue durable job inside one Store.Write. The policy/quota/jobs dependencies are narrow port interfaces defined IN store (Authorizer, QuotaReserver, JobEnqueuer); store never imports those packages. Error mapping is uniform: pgx.ErrNoRows -> apierr.NotFound, SQLSTATE class 23 -> apierr.Conflict, other driver errors -> apierr.StoreUnavailable; the raw cause is wrapped for logging only. ProjectRepository/ProjectService are the reference implementation.
- Credentials: internal/controlplane/auth owns generation/hashing/verification; internal/controlplane/store owns persistence. A secret is stored ONLY as a one-way hash plus a public, globally-UNIQUE prefix — never plaintext. Plaintext credential types implement String/GoString/LogValue/MarshalJSON returning output.Sentinel; the plaintext is reachable only via an explicit Reveal() method. High-entropy secrets (>=128 bits random) use fast unsalted SHA-256 + subtle.ConstantTimeCompare, NOT bcrypt/argon2. Authentication lookup (FindByPrefix) is the ONE deliberate non-tenant-scoped repository read — it runs before the tenant is known; the found row carries its own OrganizationID. Tenant-scoped mutations that may match zero rows report apierr.NotFound via tag.RowsAffected()==0.
- Authorization is internal/controlplane/policy: policy.Engine is a pure, total decision function — Decide(Principal, Action, Resource) -> Decision{Allow, Reason} (stable Reason codes); Authorize/AuthorizeCtx map denials onto typed apierr (Unauthenticated for a missing principal, Forbidden otherwise). Every endpoint maps to exactly one policy.Action; the action lives in policy's defaultActionCatalog (the authoritative requiredAction -> Capability map) — add new actions there or via policy.WithAction. Roles confer Capability sets (self/read/deploy/write/admin/owner/support), not individual actions; six built-ins are fixed, custom roles resolve through a CustomRoleResolver hook. Scoped Grants narrow/widen authority within an org via Scope containment over Organization->Project->Environment->Service; cross-tenant resources are denied by construction except support reads/break-glass. The principal travels on the request context via policy.WithPrincipal/PrincipalFromContext — never thread it through signatures. The store.Authorizer port is satisfied by this engine; store still never imports policy. TestPolicyMatrix exhaustively covers all built-in roles x catalogued actions.
- Request authentication is internal/controlplane/auth.Authenticator: it resolves any of the three bearer schemes (API key yk_..., human session JWT, internal worker secret) to one auth.Identity{Principal, Method}. Every invalid-credential cause collapses to the single ErrInvalidCredentials sentinel (missing creds = ErrNoCredentials) so no error is a "does this key prefix exist?" oracle; a genuine datastore failure is propagated unchanged as a typed *yerr.Error, never disguised as invalid credentials. The Authenticator depends on the narrow auth.CredentialStore port (+ APIKeyRecord/ServiceAccountRecord DTOs) so auth never imports store; the production adapter is store.CredentialReader (store imports auth, not the reverse). The HTTP wrappers are httpapi.RequireAuth(authenticator, engine, action, ResourceResolver) and httpapi.RequireInternalWorker — they authenticate, attach the principal via policy.WithPrincipal + telemetry.SetOrgID/SetPrincipalID, then authorize: missing creds 401 E_AUTH, invalid 401 E_AUTH (fixed generic message), unauthorized 403 E_FORBIDDEN (stable policy reason), dependency failure keeps its typed 5xx. ResourceResolver nil defaults to the principal's own org scope; pass a path-param resolver so a cross-tenant id is a 403, not a silent allow.
- Quota schema (0006_quota_policy_schema): a closed enum reused across tables is a Postgres DOMAIN over text + CHECK (here quota_resource over 14 dimensions, quota_enforcement_mode over hard/soft/metered/disabled); DROP DOMAIN goes in the down migration after the tables. quota_policies holds one limit per (scope, resource) where a row is EITHER a plan_default (text plan, no plans-table FK yet) OR an organization override — enforced by one table CHECK + two partial unique indexes; the checker resolves "org override else plan default". quota_usage is one counter row per (org, resource); quota_reservations are short-lived (amount>0, status active->committed|released|expired, expires_at, settled_at tied to non-active status by CHECK) and expose UNIQUE (organization_id, id) as a composite-FK target; usage_events is append-only (no updated_at/trigger, signed delta) and links reservations via a tenant-safe composite FK. An optional cross-table link inside a tenant uses a plain composite FK (MATCH SIMPLE) — NOT ON DELETE SET NULL, which would null the NOT NULL organization_id.
- Quota enforcement: the QuotaRepository (internal/controlplane/store/quota.go) is the persistence half (EffectiveLimit / LockUsage / SumActiveReservations / InsertReservation, all tenant-scoped, mutations on *Tx) and the quota.Checker (internal/controlplane/quota) is the store.QuotaReserver service half. A hard limit is enforced by LockUsage doing INSERT ... ON CONFLICT DO NOTHING then SELECT ... FOR UPDATE on the quota_usage counter row — that lock serialises concurrent reservers so they cannot both over-allocate; the decision is current+reserved+requested <= limit, reserved = SUM of active non-expired reservations. Soft/metered limits record but never reject; disabled/no-policy allow with no write. A rejection is apierr.QuotaExceeded wrapping a recoverable quota.ExceededDetail{Resource,Current,Reserved,Requested,Limit}. Quota accounting rows have no domain.Kind — ids are minted locally with a prefixed crypto/rand helper.
- Audit log (0007_audit_events, store/audit.go, internal/controlplane/audit): the immutable audit log records every authorization decision, allowed AND denied. Immutability is enforced at two layers — the table has no updated_at and a BEFORE UPDATE trigger (audit_events_reject_update) that rejects every UPDATE in the database, and AuditRepository exposes only Append + tenant-scoped ListByOrganization (no update/delete); row DELETE stays reachable only via the organizations ON DELETE CASCADE. An append-only table that must still cascade on tenant teardown blocks UPDATE only, never DELETE. The audit.Auditor (depends on the narrow Recorder port, satisfied by *store.AuditRepository) is the single place a policy.Decision becomes an AuditEvent: it pulls the principal (policy.PrincipalFromContext) + correlation ids (telemetry.FromContext) off the context, files the event under the principal's org else the resource's org, and REDACTS metadata before persistence — secret-shaped keys (token/secret/password/credential/...) replaced wholesale with output.Sentinel, every other value + the user agent scrubbed by an output.Redactor. store treats metadata as already-redacted; redaction is the audit service's contract. Auditor.Record takes the caller's *store.Tx so an audit write can share the mutation's transaction or run in its own.
- Provisioning jobs (0008_provisioning_jobs, store/job.go): the durable, idempotent queue of Dokploy provisioning work. The provisioning_jobs table is tenant-scoped (organization_id FK + composite (organization_id, project_id|environment_id|service_id) FKs so a job can never target another tenant's resource), idempotent (UNIQUE (organization_id, idempotency_key)), and exposes UNIQUE (organization_id, id) as a composite-FK target — 0008 also wires the FK that 0006 deferred (quota_reservations.job_id -> provisioning_jobs). DB CHECKs enforce the closed status set, "terminal status iff finished_at set", "lease held iff status=running", and attempts<=max_attempts; the Go state machine (store.JobStatus.CanTransitionTo, backed by the jobTransitions map: queued->running|cancelled, running->succeeded|retrying|failed|dead_letter|cancelled, retrying->running|cancelled, terminals have no edges) is the authoritative validator. JobRepository follows the ProjectRepository pattern (mutations need *Tx, reads take Querier, NotFound for cross-tenant ids); Transition locks the row FOR UPDATE, validates the edge before any write (illegal edge = apierr.Conflict), and derives lease/attempt/timestamp bookkeeping from the target status so a caller cannot leave a CHECK-violating row. error_summary is run through an output.NewRedactor() backstop on every write (Insert + Transition) — the store IS the redaction chokepoint for job errors, unlike audit metadata which the service redacts.
- HTTP idempotency (0009_idempotency_keys, store/idempotency.go, httpapi/idempotency.go): mutating endpoints are made retry-safe by httpapi.RequireIdempotency(IdempotencyStore, ttl) — middleware installed INSIDE RequireAuth (it reads policy.PrincipalFromContext to scope the key to a principal within a tenant). Safe methods and unsafe requests with no Idempotency-Key pass straight through (opt-in). The claim protocol: store.IdempotencyRepository.Claim is a WHERE-guarded upsert — INSERT ... ON CONFLICT DO UPDATE ... WHERE expires_at <= now() — so it freshly claims, transparently steals an expired row (claimed=true), or returns the existing live claim (claimed=false, RETURNING yields no row, follow-up Find reads the row the DO UPDATE attempt locked). On claimed=true the middleware runs the handler against a buffering responseCapture, then Complete records the rendered envelope (status < 500) or Release drops the claim (status >= 500, so a server failure is retried not replayed). On claimed=false: hash mismatch -> apierr.IdempotencyConflict (E_IDEMPOTENCY_CONFLICT, the only use of the new code), completed -> replay the recorded body+status with Idempotency-Replayed: true, still pending -> apierr.Conflict "already in progress". The request hash is sha256(method\npath?query\nbody); the body is buffered then restored as a fresh r.Body so the handler still reads it. Keys are scoped UNIQUE (organization_id, principal_id, idempotency_key); a completion CHECK ties status='completed' to a non-null response. The store-backed IdempotencyStore adapter (httpapi.NewIdempotencyStore) runs each repo call in its own Store.Write — RequireIdempotency is implemented and tested but not yet wired into a route (no mutating endpoints exist yet), same as RequireAuth.
- Postgres-backed worker queue (store/job.go ClaimNext, worker/queue.go): the durable queue has two halves. store.JobRepository.ClaimNext is the SKIP LOCKED claim — SELECT ... FOR UPDATE SKIP LOCKED picks the single most-eligible job (queued|retrying AND next_run_at<=now, OR running AND lease_deadline<now) so concurrent claimers skip a locked row instead of blocking, then transitions it to running inside the same Store.Write tx. An expired-lease job is reclaimed THROUGH the state machine (running->retrying->running, so attempt/lease bookkeeping stays consistent); a job past its retry budget is dead-lettered instead and the poll claims nothing. worker/queue.go is the store-backed Claimer/Lease impl: loop.go stays pure (interfaces only, fake-tested) and queue.go is the only worker file that imports store. Failure classification: worker.Terminal(err)/IsTerminal mark a permanent failure (-> failed, never retried); a plain error is transient (-> retrying with worker.Backoff bounded exponential delay, or -> dead_letter when Attempts>=MaxAttempts). StoreClaimer.complete() records every outcome on a context.WithoutCancel + timeout context — once the runner ran, the outcome write must survive shutdown; only an interrupted (un-run) job returns non-nil from Lease.Run so the loop releases it. The JobRunner (real Dokploy provisioner) is still injected/faked; cmd/yalla-worker stays on NoopClaimer until that runner lands.

  - SKIP LOCKED + the Store.Write row lock is the whole concurrency story: a
    claimer's open transaction holds the row, a peer's SELECT ... SKIP LOCKED
    skips it, the transition to running commits with the lock held. No queue
    library needed.

    (running->retrying->running) avoids adding a running->running self-edge to
    jobTransitions and keeps attempt counting honest — a reclaim is just
    another retry.

    context detached from cancellation (context.WithoutCancel + timeout). If it
    used the live ctx, a job that finished exactly as shutdown began would fail
    its own success-write, get treated as interrupted, and be released for a
    duplicate run. Only a genuinely un-run (interrupted) job returns non-nil.

    flaky: a job locked by a peer's still-open tx looks empty via SKIP LOCKED.
    Workers must retry-until-drained with a deadline guard.
  - worker_test (package worker_test) cannot reach store/schema_test.go's
    seedOrg helpers — re-seed the org with a local INSERT helper.
